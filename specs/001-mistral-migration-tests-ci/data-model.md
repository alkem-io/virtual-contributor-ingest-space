# Data Model: Migrate to Mistral Platform with Tests and CI

This service is a data pipeline — it does not own a persistent data model.
The entities below represent the runtime data structures flowing through
the pipeline stages.

## Ingestion Event (Input Message)

Received from the RabbitMQ input queue.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| bodyOfKnowledgeId | string | yes | Unique identifier of the space/knowledge base |
| type | BodyOfKnowledgeType | yes | `alkemio-space` or `alkemio-knowledge-base` |
| purpose | IngestionPurpose | yes | Purpose of the ingestion run |
| personaId | string | yes | Persona identifier for the virtual contributor |

### BodyOfKnowledgeType (enum)
- `alkemio-space`
- `alkemio-knowledge-base`

## Ingestion Result (Output Message)

Published to the RabbitMQ output queue.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| bodyOfKnowledgeId | string | yes | Echo of input identifier |
| result | IngestionResult | yes | `SUCCESS` or `FAILURE` |
| error | ErrorDetail | no | Present only on failure |
| startedAt | number | yes | UTC timestamp (ms) |
| finishedAt | number | yes | UTC timestamp (ms) |

### ErrorDetail

| Field | Type | Description |
|-------|------|-------------|
| code | ErrorCode | Categorized error code (e.g., `VECTOR_INSERT`) |
| message | string | Human-readable error description |

## Document Chunk (Internal)

Produced by the text splitter, stored in ChromaDB.

| Field | Type | Description |
|-------|------|-------------|
| id | string | `{documentId}-{type}-chunk{index}` |
| pageContent | string | Chunk text content (min 200 chars after merging) |
| metadata | ChunkMetadata | Sanitized to primitives only |

### ChunkMetadata

| Field | Type | Description |
|-------|------|-------------|
| documentId | string | Source document identifier |
| type | DocumentType | Source document type |
| embeddingType | string | `chunk` or `summary` |
| chunkIndex | number | Position within the document |
| source | string | URL of the source entity |

## ChromaDB Collection Schema

One collection per body of knowledge, named by `bodyOfKnowledgeId`.

| Component | Description |
|-----------|-------------|
| ids | String IDs: chunk IDs + `{docId}-{type}-summary` + `body-of-knowledge-summary` |
| documents | Text content (chunks + summaries) |
| metadatas | ChunkMetadata records (primitives only: string, number, boolean, null) |
| embeddings | Generated by Scaleway endpoint (model: configurable via `EMBEDDINGS_MODEL_NAME`) |

## State Transitions

The ingestion pipeline is stateless between runs. Within a run:

```
IDLE → PROCESSING (message received)
  → FETCHING (Alkemio API calls)
  → CHUNKING (text splitting + short-chunk merging)
  → SUMMARIZING (Mistral API calls for docs with >3 chunks)
  → EMBEDDING (Scaleway API calls)
  → STORING (ChromaDB upsert)
  → COMPLETE (result published: SUCCESS)

Any stage failure → ERROR (result published: FAILURE with error code)
```

There is no persistent state between ingestion runs. Each run replaces
the previous collection contents atomically.
